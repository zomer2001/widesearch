# 七维字段契约 v2

七维及现有物理表保持不变。目录中每个字段都有适用对象、类型规则、来源要求、存储映射和缺失策略。`definition_status=reviewed` 表示有具体边界说明，`type_template` 表示只完成类型级规范，不能宣称已经逐列解决全部语义歧义。

## 本次实际细化

新增六个独立属性轴：

| 字段 | 含义 | 示例 |
|---|---|---|
| technology_computational_paradigms | 计算方法范式，可多选 | 规则、传统统计学习、深度学习 |
| technology_learning_modes | 学习方式，可多选 | 监督学习、自监督学习、强化学习 |
| technology_detection_pipeline | 目标检测阶段组织 | 单阶段、两阶段 |
| technology_backbone_architectures | 原文明示的主干架构 | CNN、Transformer |
| product_application_settings | 应用场所 | 港口、机场、边境 |
| product_mission_purposes | 任务目的 | 监测、巡检、反制 |

已有 `product_operating_domains/product_target_domains/product_target_types` 继续使用，分别表达产品自身环境、目标环境、目标类别。已有算法家族/具体模型字段继续使用，不重复建列。

旧 `technology_route_branch` 保留兼容显示；新抽取优先拆成独立轴。`technology_technical_route` 用于命名的路线实体，不再把“深度学习”这种范式与具体路线混为一列。原有数据不自动重写。

## 类型与受控词

- 枚举：只在真正有限的轴建立封闭词表及中英同义词，例如运行环境、开源状态、检测流程。新值保留待映射。
- 开放词：技术专名、架构名、场所等允许增长；一个词能表达时用短词，无法可靠概括则保留原句到说明/待映射。
- 布尔：只接收明确支持/否定。未提及保持空；计划/部分支持不能变成 true。
- 测量：保留原值、原单位、上下限、对象、条件和版本。程序仅规范已知单位同义写法，不做缺乏依据的换算。
- 多值：数组或多行关联表，一项一个对象；重复行通过 row_key 关联，不为每个新技术增加一个布尔列。
- 描述：原理、问题、来源评价等允许完整文字，不能为了“一词化”损失事实条件。

抽取模型只提出记录；确定性程序检查字段和类型、原文引用、规范词及对象匹配，再生成参数化 SQL。合法 SQL 不意味着语义正确，候选及冲突需要在写入预览中明确显示。

契约和新增字段仅在预演数据库副本中安装；业务数据库更新由确认后的 SQL 计划执行。打包操作不修改业务数据库。
