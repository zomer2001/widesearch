# 可选创新模块接入设计

2026-10-29。本文是接入规范，尚未迁移或启用创新算法。当前工作台保持基础版运行方式。用户所指“我的创新”仍待确认；下文把旧研究目录中的 P1/P2 作为候选实例，不据此默认纳入产品。

## 建议：在当前工作台受控回接增量

保留当前后端、模型选择、资料库、调度和前端，按模块接口逐段迁入经过验收的算法增量。默认模块集合为空，原基础流程保持原行为。采用同一套任务、证据和事件标识，增强结果能直接进入现有过程图和来源查看器。

暂不另复制一整套“增强后端”。两个后端会分别积累模型适配、资料路径迁移、API、停止操作和前端状态兼容工作；旧 P1/P2 又依赖主调度内的提交屏障，无法作为任务结束后的外部处理器可靠补上。确有独立运行时依赖的未来模块可以进独立工作进程，但仍使用统一任务契约，不能并行争夺调度权。

## 已核实的旧代码条件

| 候选模块 | 旧开关与已实现路径 | 迁移约束 |
| --- | --- | --- |
| P1 证据适用性修订 | `enable_p1_evidence_reasoning=False`；抽取标注、时间预检、已确认修订、用途失效、受影响任务重排、旧结果拒绝 | 确认新旧来源和版本后才能修订；规则本身不自动判定来源可信度，也不把较晚采集等同于较新事实 |
| P2 目标与采集经验 | `enable_p2_context_memory=False`；原压缩器增加目标快照、经验反馈、经验选择、版本失效 | 复用共同版本票据与读集，但不能因此自动启用 P1 时间推理；P2 压缩器与旧历史裁剪器不能同时重复改写输入 |
| 共同版本保护 | `p1_runtime.py`、`revision_state.py`、`revisions.py` 等 | 追踪一旦写入工作区，不能靠关闭全局开关绕过旧结果检查；只有原文引用无法补造历史真实读集 |

旧参数还包括 `p2_context_window`、`p2_summary_fraction=0.08`、`p2_max_experiences=3`、`p2_experience_max_chars=2400`。窗口应取实际模型服务允许值；当前 CLI 桥接还有保守输入限制，不能仅把模型标称窗口填进模块设置。

旧代码把多个开关读自进程级 `settings`。Web 任务不能通过临时改写这些全局值来切换模块，否则并行任务可能串用配置。现有任务级模型绑定可以借鉴，但模块选择还必须持久化。

特别需要区分两条本地路径：`local_search_pipeline` 是研究调度中的本地检索子代理；当前“本地资料直接问答”调用 `create_qa_graph`，使用 `DynamicTrimMiddleware` 和 `LocalQAMiddleware`，没有进入旧 P1/P2 研究流水线。只给直接问答增加 P1/P2 菜单，算法不会因此生效。

代码依据：旧 [settings](../../SearchOS/searchos/config/settings.py)、[pipelines](../../SearchOS/searchos/harness/middleware/pipelines.py)、[运行票据](../../SearchOS/searchos/harness/p1_runtime.py)、[直接问答入口](../../SearchOS/searchos/agents/local_search/__init__.py)。旧验证以固定响应演示为主，不等于当前工作台已经完成真实增强任务验收。

## 任务级固定配置

模块注册项至少包含稳定 ID、实现版本、状态格式版本、依赖模块、支持的任务模式、参数校验器和事件类型。只有代码已接线且对应模式已通过验收，注册项才标记为可用。未实现模块不提供可提交的启用按钮。

任务启动前解析一次请求，形成不可变 `RunModuleConfig`，与模型选择、资料范围、预算一起保存到工作区清单。最少记录：

- `schema_version`、`run_id`、`requested_modules`、`resolved_modules`；
- 各模块 `implementation_version`、已校验参数、依赖关系；
- `source_mode`、模型及窗口信息、配置指纹。

新任务省略模块字段时使用基础版；续问省略字段时沿用原任务清单。修改模块组合需要新建工作区，不能在已有追踪记录的任务中直接降级。恢复任务时先校验实现和状态版本，发现不兼容应明确报告，不能静默退回基础版并继续发布旧结果。

运行时显式传递配置到会话、中间件构造器及抽取协调器。必要时用 `ContextVar` 向子任务传播，但持久化清单是恢复与校验依据，不依赖某个请求仍存活的上下文。未知模块、未知参数、不支持的任务模式在启动前拒绝。

现有 `.workbench-engine.json` 只允许读取引擎字段。模块配置应使用独立版本化清单，或同步扩展读写白名单；不能只写入额外字段而让恢复读取时丢弃。

## 分批迁移范围

| 批次 | 需要迁入或适配的部分 | 完成标志 |
| --- | --- | --- |
| 1. 契约与空模块路径 | 模块注册、任务配置、版本化状态扩展、事件契约；基础路径不实例化增强中间件 | 基础任务与当前基线行为一致，新增模块不能跨任务串用 |
| 2. 共同保护 | `socm/revision_state.py`、`socm/revisions.py`、`harness/p1_runtime.py`、`p1_reports.py`；适配 Workspace、读取工具、抽取提交、任务/章节/报告发布入口 | 真实读集、原子提交、迟到回调拒绝、来源权限和工作区恢复形成闭环 |
| 3. 候选 P1 | `claim_annotations.py`、`temporal.py`、`claim_enrichment.py`、冲突预检、`p1_repair.py`；适配 lifecycle/scheduler/writer | 明确时间演化可保留；已复核修订只重排受影响任务；版本变化阻止旧发布 |
| 4. 候选 P2 | `context_memory.py`、`p2_memory.py`、原压缩器增量、pipelines 和完成生命周期反馈 | 目标原文保留、真实新增证据计分、相关经验被选用，修订使旧经验和摘要失效 |
| 5. 本地直接问答 | 为 QA 接入真实观察/证据、稳定回答任务、执行票据、结果发布及增强上下文；按需补独立流程适配 | QA 模式的模块确实触发，且资料范围、引用和停止行为仍正确 |

P1 的 RDF/本体导出可以作为可选审计功能，不是基础运行或有限时间规则的强制依赖。语料实验、旧研究输出、DocETL、PAGE-RAG 和其他研究分支不随 P1/P2 自动迁入。迁移采用逐文件差异审查，不能覆盖整个 `session.py`、`lifecycle.py` 或 `pipelines.py`，以免丢失工作台新模型和状态适配。

## 过程图显示真实触发

“已配置”“当前可用”“本次已触发”“本次完成”“本次失败”是不同状态。用户启用模块但任务未遇到适用条件时，显示“已启用，尚未触发”。不能按照勾选项、经过时长或动画位置生成执行成功。

模块成功事件应来自已提交的运行状态。建议在同一个 SOCM 原子更新中保存事件记录和状态版本，再经现有 `StateStream` 的快照/增量发送；进度通知可单独记录，但不能先发送成功再尝试提交。事件应含 `event_id`、`sequence`、`run_id`、`task_id`、模块/实现版本、触发原因、输入/输出引用、状态版本、耗时及可知用量，重放按事件 ID 去重。

| 图上事件 | 真实依据 | 可展开的信息 |
| --- | --- | --- |
| P1 时间预检完成 | 已提交的 `EvidenceComparison`，且 `method=p1_rule` | 两侧证据、有效期、适用口径、所用规则 |
| 修订已确认 | `ConfirmedEvidenceRevision` 与已提交 `RevisionImpact` | 新旧版本、确认原因、受影响任务和仍保留的支持 |
| 局部修复完成 | 调度生命周期实际完成且产物版本已通过发布校验 | 重跑任务、未动分支、拒绝的迟到结果、当前报告版本 |
| P2 经验登记/选用 | 已提交的 `ExperienceCard`；当前请求实际使用的 `ContextPacket` | 查询/路由、来源、增量证据、被选原因和版本 |
| 压缩完成/重建 | 已提交的压缩检查点与 `compaction_metrics` | 目标版本、保留经验、估算输入量、摘要调用、失效原因 |

状态图只展示任务动作和证据关系，不展示模型内部思考。估算 token、模型实际计费 token 和未知费用分别表达。图节点点击后使用现有来源面板回到原文，不把“有引用”标成“已独立证实”。

## 开放可选入口前的验收

1. **基础等价**：空模块配置保持既有调用路径、来源约束、输出和停止语义；模块目录缺失时基础版仍能启动。共同版本保护单独评估，不能把其收益全部归给 P1/P2。
2. **任务隔离**：基础/P1/P2/组合任务并行运行互不串配置；续问、重启、取消和后台抽取都使用原任务的配置及版本。
3. **P1 行为**：正常时间演化、同期间冲突、未知日期、替代支持、无关分支、确认重放、迟到结果、报告重建分别验证。确定性夹具和真实模型样例分开记录。
4. **P2 行为**：多次用户修正、压缩前后目标、真实派发前基线、经验去重、实际选用和修订失效分别验证；失败摘要调用计入开销。
5. **模式覆盖**：Web、Hybrid 与直接 Local QA 分别验收；未接线模式不得显示该模块可启用。模型选择与算法选择独立，逐个验证所支持模型的结构化输出及窗口。
6. **前端回读**：在线、刷新、断线重连、历史回放得到同一事件及版本；启用但未触发不显示已完成；修复未结束的报告不显示为有效最终结果。

用户确认创新内容后，先做一个固定资料、可重复触发的最小增强任务，再将通过验收的模块开放到选择界面。此前仅保留本设计文档，不改变当前基础任务行为。
